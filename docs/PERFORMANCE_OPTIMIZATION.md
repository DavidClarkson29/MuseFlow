# MuseFlow 性能与功耗优化方案

## 1. 文档目的

本方案用于降低 MuseFlow 原型在本地开发和浏览器运行时的 CPU、GPU、内存与电量消耗，同时保证现有视觉、卡片尺寸、排版、拖拽手感和产品功能保持 1:1 不变。

优化分为两层：

1. **开发环境治理**：确保同一工程始终只运行一个预览服务器。
2. **网页运行时优化**：停止无意义的持续重绘，减少画布事件计算、React 重渲染和定时器数量。

## 2. 已确认的主要问题

### 2.1 重复启动预览服务器

诊断时发现该工程曾同时运行 28 个 Vite 实例。每个实例都会持有 Node.js 进程、文件监听器和 WebSocket 服务。即使单个实例占用不高，大量累积后也会明显增加内存、唤醒次数和系统功耗。

根因：每次验证都使用新端口启动服务，而旧服务没有在任务结束时关闭。

### 2.2 选中卡片永久运行阴影动画

`src/index.css` 中的 `.sel-breathe` 以 `1.9s infinite` 持续改变 `box-shadow`。选中任意卡片后，即使用户完全不操作，浏览器仍需持续进行样式计算和像素重绘。

大面积模糊阴影属于高成本绘制属性，和透明背景、缩放画布以及毛玻璃叠加时成本更高。

### 2.3 画布在每次鼠标移动时遍历节点与端口

`src/components/Canvas.tsx` 的 `handlePointerMove` 在普通鼠标移动期间仍会：

- 遍历全部可见节点，寻找卡片边缘；
- 遍历节点的全部输入和输出端口；
- 计算距离和吸附候选；
- 尝试更新 Ghost Port、端口悬停和分组目标状态。

卡片数量增加后，这部分开销会近似随节点和端口总数线性增长。

### 2.4 全局拖拽监听长期存在

Demo 和作品抽屉组件在挂载期间持续注册 `window.pointermove`、`pointerup` 等事件。虽然没有拖动时处理函数会提前退出，但浏览器仍需分发事件并进入处理函数。

### 2.5 每张播放卡片拥有独立定时器

Demo 与 Remix 类卡片播放时各自运行 `100ms` 更新一次的定时器。多个卡片同时播放时，会形成多个独立更新源和 React 重渲染。

### 2.6 毛玻璃与动态内容叠加

左侧栏使用约 `24px` 的 `backdrop-filter`。静态毛玻璃本身通常可以接受，但当其后方存在不断变化的阴影、卡片动画或画布移动时，会增加 GPU 合成压力。

## 3. 优化约束

所有性能改动必须满足以下条件：

- 不改变现有 UI 排版、卡片尺寸、颜色和层级；
- 不改变拖拽坐标、抽屉逻辑和卡片生成数量；
- 不删除现有功能；
- 不通过降低图片清晰度或关闭关键视觉效果掩盖问题；
- 所有优化均需支持单独回滚；
- 每一阶段完成后必须进行视觉截图对比和交互回归。

## 4. 优先级与实施顺序

| 优先级 | 工作项 | 预期收益 | 风险 |
| --- | --- | --- | --- |
| P0 | 单实例预览服务器 | 立即消除重复 Node 进程 | 低 |
| P0 | 停止永久阴影重绘 | 显著降低页面空闲 GPU 使用 | 低 |
| P1 | Pointer Move 按帧节流 | 提升拖拽和鼠标移动流畅度 | 中 |
| P1 | 节点和端口坐标缓存 | 降低画布节点增多后的计算量 | 中 |
| P1 | 拖拽监听按需注册 | 减少空闲事件分发 | 低 |
| P1 | 播放进度统一调度 | 降低多卡片播放时的更新数量 | 中 |
| P2 | 拖动临时状态与项目状态分离 | 降低 React 更新和自动保存压力 | 中高 |
| P2 | 视口裁剪与卡片虚拟化 | 支持更大规模画布 | 高 |
| P2 | 增量保存 | 降低大项目序列化与 IndexedDB 写入 | 中 |

## 5. P0：开发环境单实例治理

### 5.1 固定端口并禁止自动递增

开发命令应固定一个端口并启用 `--strictPort`：

```json
{
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5202 --strictPort"
  }
}
```

端口已被占用时，命令应直接失败并提示复用当前服务，而不是启动下一个端口。

### 5.2 使用 PID 文件管理生命周期

建议增加 `scripts/dev-server.mjs`：

- 启动时把当前 PID 写入 `.museflow-vite.pid`；
- 启动前读取旧 PID；
- 同时验证 PID 对应进程名称、当前工程目录和监听端口；
- 验证一致后发送 `SIGTERM`；
- 在 `SIGINT`、`SIGTERM` 和正常退出时清除 PID 文件；
- 禁止使用 `killall node` 或宽泛的 `pkill vite`。

### 5.3 工作流规范

- 开发期间始终复用一个 URL；
- 修改代码依靠 Vite HMR，不重新启动服务器；
- 只有服务崩溃或配置改变时才重启；
- 任务结束前检查监听端口；
- CI 和临时验证使用具有自动清理能力的子进程。

## 6. P0：停止页面空闲时持续重绘

### 6.1 重构选中光晕

保留现有视觉，但不再动画卡片主体的 `box-shadow`。

推荐结构：

- 卡片主体保持静态边框和静态阴影；
- 使用绝对定位伪元素绘制光晕；
- 只动画伪元素的 `opacity` 或轻微 `transform`；
- 动画在选中后播放一次，或在 600–800ms 后停在稳定状态；
- 不使用永久 `infinite` 阴影动画。

`opacity` 和 `transform` 更容易由合成层处理，通常不需要每帧重绘卡片内容。

### 6.2 页面不可见时暂停动态效果

监听 `document.visibilityState`：

- 页面进入后台时暂停装饰动画；
- 停止非必要进度刷新；
- 恢复前重新同步真实音频时间；
- 不在后台继续运行 shimmer 或呼吸效果。

### 6.3 尊重减少动态效果设置

增加：

```css
@media (prefers-reduced-motion: reduce) {
  .sel-breathe,
  .shimmer,
  .ai-dot-1,
  .ai-dot-2,
  .ai-dot-3 {
    animation: none !important;
  }
}
```

## 7. P1：画布输入事件优化

### 7.1 Pointer Move 每帧最多计算一次

原始指针事件只保存到 `ref`，真正计算放入一个共享 `requestAnimationFrame`：

1. 收到 Pointer Move，更新最新坐标；
2. 若本帧已有计算任务，不再创建新任务；
3. 下一动画帧读取最后一次坐标；
4. 完成一次吸附、端口和拖动计算。

这样可以避免高频触控板或鼠标在一帧内触发多次 React 计算。

### 7.2 按交互状态分流

Pointer Move 应按以下顺序快速退出：

- 正在平移：只更新平移；
- 正在拖卡片：只更新拖动预览与分组候选；
- 正在连线：只检查连线目标；
- 普通悬停且距离卡片较远：不遍历端口；
- 只有接近卡片边缘时才进行 Ghost Port 计算。

### 7.3 缓存端口几何信息

当节点位置、尺寸或端口发生变化时，生成一次扁平化几何缓存：

```ts
type CachedPort = {
  nodeId: string
  portId: string
  x: number
  y: number
  isInput: boolean
}
```

鼠标移动时只查询缓存，不重复执行 `nodes.find`、数组拼接和绝对坐标换算。

### 7.4 卡片数量较多时使用空间索引

当可见节点超过约 80–100 个时，引入简单网格索引：

- 将画布划分为固定尺寸网格；
- 节点只登记到覆盖的网格；
- Pointer Move 只检查鼠标所在网格及相邻网格；
- 拖动结束后更新索引。

## 8. P1：拖拽与播放调度

### 8.1 拖拽监听按需注册

只有 `pointerdown` 确认开始拖动后，才注册：

- `window.pointermove`；
- `window.pointerup`；
- `window.pointercancel`。

在拖动完成、取消或组件卸载时立即移除。Demo 与作品抽屉应共用一个拖拽控制 Hook，避免重复实现。

### 8.2 播放进度使用统一时间源

优先使用真实 `<audio>`：

- 通过 `currentTime` 获取真实时间；
- 使用 `timeupdate` 或共享的低频调度器刷新 UI；
- 暂停后注销更新；
- 不可见卡片不刷新文本和进度条；
- 页面恢复可见时一次性校准进度。

如果仍需模拟播放，应使用一个全局时钟管理所有正在播放的卡片，而不是每张卡片一个 `setInterval`。

## 9. P2：React 状态与保存架构

### 9.1 拖动过程不写正式节点数组

拖动时：

- 使用 `ref` 保存临时坐标；
- 直接更新卡片外层 `transform`；
- 每帧只更新当前拖动卡片；
- `pointerup` 时一次性提交节点位置。

这能避免每次 Pointer Move 都创建新的 `nodes` 数组并触发画布级重渲染。

### 9.2 组件隔离

- `NodeCard` 使用 `React.memo`；
- 传入稳定回调，避免无关卡片因为函数引用变化而重渲染；
- WireLayer、抽屉、右侧机架和画布卡片拆分更新边界；
- 播放状态保留在卡片局部或独立音频 Store 中。

### 9.3 自动保存只处理稳定状态

- 拖动期间不触发项目保存；
- 在 `pointerup` 或语义操作完成后标记项目为 dirty；
- 使用 `requestIdleCallback` 安排序列化；
- 只写入变化的节点与连线；
- Blob 素材继续按 `assetId` 去重，不重复存储。

## 10. 毛玻璃和阴影使用规范

- 毛玻璃只用于固定、面积较小的浮层；
- 避免在毛玻璃下方播放大面积阴影动画；
- 大阴影保持静态；
- 动态高光优先使用伪元素的透明度；
- 不要给全部节点设置 `will-change`，只在交互开始时临时设置；
- 交互结束后移除 `will-change`，避免长期占用显存。

## 11. 验收指标

### 11.1 开发环境

- 同一工程监听端口数量：**1**；
- 服务重启后不存在遗留 Vite 进程；
- URL 固定，不随每次修改变化。

### 11.2 页面空闲状态

- 未播放、未生成、未拖动时不存在 JavaScript 周期定时器；
- 不存在永久运行的大面积 `box-shadow` 动画；
- 页面进入后台后装饰动画全部暂停；
- 空闲 CPU 长期目标：约 **1–2% 以下**；
- 浏览器不持续产生 Paint 事件。

### 11.3 交互状态

- 单次 Pointer Move 计算目标：**4ms 以内**；
- 100 张卡片下拖拽目标：接近 **60 FPS**；
- 拖动时只有当前卡片及必要图层更新；
- 多卡片播放不会为每张卡片创建独立高频定时器。

### 11.4 功能回归

- Demo 和作品卡片抽屉尺寸不变；
- 抽屉内外卡片尺寸、排版完全一致；
- 卡片拖出位置和手感不变；
- 四素材占比显示正确且总和为 100%；
- 真实素材导入、播放、保存、恢复正常；
- 音频右键下载和歌词导出正常；
- 测试模式行为不变。

## 12. 测试方法

每个阶段至少执行：

1. TypeScript：`tsc --noEmit`；
2. 生产构建：`vite build`；
3. 浏览器空闲 30 秒性能录制；
4. 连续拖动卡片 20 秒；
5. 同时打开 Demo 和作品抽屉；
6. 播放两张以上音频卡片；
7. 切换后台 30 秒后恢复；
8. 保存、刷新并恢复项目；
9. 优化前后同尺寸截图像素级对比。

建议记录以下数据：

- 主线程 Scripting、Rendering、Painting 时间；
- GPU 与 CPU 使用率；
- JS Heap；
- Long Task 数量；
- 每秒 React Commit 次数；
- Pointer Move 平均耗时和 P95；
- 当前 Vite 进程数量。

## 13. 推荐执行批次

### 批次 A：低风险快速收益

- 固定端口和单实例管理；
- 停止永久阴影动画；
- 页面隐藏时暂停动画；
- 拖拽监听按需挂载。

### 批次 B：画布性能

- Pointer Move RAF 节流；
- 端口坐标缓存；
- React.memo 与稳定回调；
- 播放进度统一调度。

### 批次 C：大画布能力

- 拖动临时状态层；
- 视口裁剪；
- 空间索引；
- 增量保存。

每个批次应独立提交，完成视觉和功能回归后再进入下一批，以便出现问题时精确回滚。
